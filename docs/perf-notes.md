# 성능 메모 (integrate/immersive, a71c448 병합 이후)

증상: 기지 내부와 헬멧 착용 전환(HUD 진입)에서 끊김. 측정은 `tools/perf-measure.mjs` (헤드리스 Chrome, 1600×900, Apple M2 Pro, ANGLE Metal).
헤드리스 수치는 실제 창과 다르고, 측정 중 다른 워크트리의 헤드리스 Chrome이 GPU를 같이 써서 ±10 fps 정도 흔들린다.

## 원인
- 실내 한 프레임에 장면(197만 삼각형)을 세 번 이상 그림: 본 패스 + AO 법선/깊이 패스(지형 141만 포함) + 2048² 그림자 맵 3장(태양, 작업대 스폿 2개)을 매 프레임 갱신. 합계 575만 삼각형, 드로콜 470–816.
- 지형이 통짜 메시 2개(82만 + 32만)라 시야 밖도 전부 그림.
- 헬멧 전환 첫 프레임에 우주복 모델·헬멧 내부·경로 리본 셰이더를 처음 컴파일하고 텍스처를 올림(프로그램 68 → 111개): 330–450 ms 정지.
- 레티나(DPR 2)에서는 픽셀 비용이 지배적: 실내 합성 1.5배율 + MSAA×4 + GTAO, 실외 2배율.
- 이동 적분이 dt를 50 ms로 잘라서 20 fps 아래에서는 걷는 속도 자체가 느려짐.

## 바꾼 것
- `src/main.js`
  - 그림자 맵은 드리우는 물체가 움직일 때만 갱신(문, 보이는 대원 모델, 로버, 태양 타깃 스냅). `light.shadow.autoUpdate = false` + 변경 시 `needsUpdate`.
  - 로딩 화면 뒤에서 모든 물체를 보이게 한 채 실내/실외 경로를 한 번씩 그려 셰이더 컴파일·텍스처 업로드를 미리 끝냄.
  - 렌더러 픽셀 배율 상한 2 → 1.5.
  - 걷기/주행은 실제 프레임 시간(최대 0.25 s)을 50 ms 이하 부분 스텝으로 적분. 카메라 연출은 기존 50 ms 상한 유지. W 전용 규칙은 그대로.
  - `__mw.habitatRenderer` 디버그 핸들 추가(측정용).
- `src/render/habitat-renderer.js` (민수 님 파일)
  - AO 법선/깊이 패스에서 지형·로버 그룹 숨김(`createHabitatRenderer(..., { outdoor })`).
  - AO 해상도 0.75 → 0.5배, GTAO 샘플 16 → 8, 디노이즈 탭 16 → 12.
  - 실내 합성 배율 상한 1.5 → 1.25 (DPR 1 화면에는 영향 없음).
- `src/world/terrain.js`: 지형 격자를 정점 버퍼를 공유하는 타일 메시(1 m: 64칸, 20 m: 80칸)로 나눠 시야 밖 타일을 컬링. `terrain-hirise-1m` / `terrain-ctx-20m`은 이제 Group.
- `src/world/habitat-*.js`, `base.js`, `helmet.js`는 건드리지 않음.

## 보이는 차이
- DPR 1 캡처에서는 실내·헬멧 전환 모두 육안 차이 없음(AO가 아주 약간 부드러움).
- 레티나에서는 실내가 1.5 → 1.25배율, 실외가 2 → 1.5배율이라 가장자리가 약간 부드러워짐. 모니터 상세 화면과 HUD는 DOM이라 그대로 선명.
- 타이밍 차이: 대원 모델이 안 보이는 1인칭 도보 중에는 태양 그림자가 4 m 스냅마다만 갱신됨(드리우는 물체가 안 움직이므로 결과는 동일).

## 남은 것
- 실내는 여전히 픽셀 비용이 큼: RectAreaLight 2개(약 4–5 ms), 스폿 그림자 PCF 샘플링, MSAA×4 + FXAA. 더 필요하면 합성 배율 1.0 또는 MSAA 2.
- 창문 너머 지형은 벽에 가려져도 시야 절두체 안이면 그림(약 85만 삼각형).
- 이번에는 `npm test`, `vite build`, 위 측정과 캡처만 실행. integration / stage1 / rover / stage2 브라우저 검사는 돌리지 않음(이전에 실패하던 integration 2건 미확인).
