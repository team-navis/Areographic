## 2. 키 배정 (모드별로 분리)

키 입력은 `src/main.js`에서 모드에 따라 한 갈래로만 처리한다. 같은 숫자 키가 두 곳에서 동시에 처리되는 경로가 없다.

| 모드 | 키 | 동작 | 출처 |
| --- | --- | --- | --- |
| 관제석 (`pad`) | `1` `2` `3` | 왼쪽·중앙·오른쪽 모니터 열기 | 팀원 |
| 관제석 (`pad`) | `F`, `Esc` | 모니터 확대/돌아가기, 상세 화면 닫기 | 팀원 |
| 기지 안 (`habitat`) | `W` `A` `S` `D`, 방향키, `F` | 자유 보행, 시선, 바라보는 모니터 열기 | 팀원 |
| 기지 밖 (`hud`) | `W`, `E`, `Shift` | 경로 전진, 로버 승하차, 로버 배속 | 우리 |
| 기지 밖 (`hud`) | `1`(`Enter`), `2`, 휠·`[` `]`, `M`, `V` | 버튼 1, 버튼 2, 다이얼 회전, 다이얼 누름(미니맵), 음성 | 우리 |

기지 안에서는 `1` `2` `3` `E` `M` `V` `Shift`가 아무 일도 하지 않는다. 기지 밖에서는 `A` `S` `D` 방향키 `3` `F`가 아무 일도 하지 않는다.

## 3. 팀원 HUD의 클릭 조작을 바꾼 방법

팀원 브랜치의 외부 HUD에는 누르는 단추가 셋 있었다. 통합본에서는 다음처럼 바꿨다.

| 팀원 구현 | 통합본 |
| --- | --- |
| `＋ 우주복·임무 상태` 토글 단추 | 없앰. 버튼 2(`2`)로 연다. 음성 "상세"로도 여닫는다 |
| 상세 패널의 `×` 닫기 단추, `Esc` 닫기 | 없앰. 버튼 2로 닫는다 |
| 패널 내용: 계획, 경로 진행, 산소 모델, 남은 이동 시간 계산 방식, 지형 출처, 미연결(심박·압력·체온, 전력·통신 지연, 버디 위치) | 그대로 가져와 표시 전용 층으로 둠. "미연결" 표기 유지. 색은 우리 HUD의 "없는 자료" 색(청록, Table F.5-1) |
| `#hud-act` 승하차 단추 (클릭 가능) | 단추가 아닌 안내 표시(`E · 로버 탑승`). `E` 키로만 동작 |
| 패널이 열리면 이동·승하차·시선 입력 차단, 포인터 잠금 해제 | 차단하지 않음. 층은 누를 것이 없는 표시이므로 열어 둔 채 걸을 수 있다 |

버튼 2의 동작 순서:

- 카드가 있을 때(도착 알림, 작업, 기지 도착, 임무 종료): 카드 접기/펴기. 통합 전과 같다.
- 카드가 없을 때(이동 중): 기본 → 우주복·임무 상태 층 → 부가 정보 숨김 → 기본. 통합 전에는 기본 ↔ 부가 정보 숨김 두 단계였다.
- 층이 열려 있으면 버튼 2는 항상 층을 먼저 닫는다.

음성: 메모 화면이 아닐 때 `V`를 누르는 동안 브라우저 음성 인식이 "상세"라는 단어를 들으면 층을 여닫는다. 다른 음성 명령은 없다. 실제 마이크 인식은 검증하지 않았다. 검사에서는 인식된 글자를 넘기는 훅(`hud.voiceCommand`)으로만 확인했다.

층에는 팀원 쪽 계산을 그대로 썼다. 정지 중 현재 속도 0.0 m/s, 남은 이동 = 남은 경로 ÷ 설정 속도(`src/hud/telemetry.js`). 복귀 중에는 기지까지 남은 경로로 계산한다.

위치는 왼쪽 가장자리(브랜드 판 자리)다. 1600×900 화면에서 가로 136~466 px이고, 가운데 비움 영역(가로 30~70%)은 480 px에서 시작한다.

### 통합본에 들어오지 않은 팀원 HUD 요소

팀원 HUD의 계기 배치(왼쪽 위 목적지·계획 머리말, 큰 숫자의 산소·남은 거리 계기, 경로 진행률 막대, 세이지·앰버 색)는 기지 밖에서 쓰지 않는다. 기지 밖은 우리 HUD를 따른다는 결정 때문이다. `src/hud/hud.css`는 층의 스타일만 남겼다. 팀원이 이 배치를 살리고 싶다면 팀에서 다시 정해야 한다(5절).

## 5. 팀에서 확인할 것

- (민수 님) 외부 HUD 배치: 팀원 HUD의 계기 디자인을 기지 밖에서 쓰지 않는 것에 동의하는지. 살리고 싶은 요소가 있는지.
- (민수 님) 상태 패널을 열어도 이동을 막지 않게 바꾼 것. 원래는 패널이 조작 화면이라 막았다.
- (민수 님) `stations.js` 출처 탭 문구 수정, `hud.css` 축소, 단위 검사 픽스처 변경이 의도와 맞는지.
- (민수 님) 시작 화면 이름: 우리 쪽 "mars walk", 팀원 쪽 "NAVIS / HABITAT ALPHA". 통합본은 시작 화면·관제석은 팀원 표기, HUD 판은 "mars walk"로 남아 있다. 제품명은 미확정이다.
- (민수 님) 오른쪽 모니터(대원·기지 운영)와 모니터 미리보기는 `st.arrived`만 보고 상태를 적는다. 현장 작업·복귀·기지 도착·임무 종료 단계가 구분되어 보이지 않고, 복귀 중에는 진행 거리가 줄어드는 숫자로만 보인다. 중앙 PAD 홈은 단계를 표시한다. 통합에서는 고치지 않았다.
- 버튼 2 순서(기본 → 상세 → 부가 정보 숨김)와 음성 단어 "상세"는 이번 통합에서 정한 가정이다.
- 임무가 끝나도 대원은 경사로 아래에 남는다. 에어록으로 다시 들어가는 동선은 어느 쪽에도 없다.
- 우리 `src/hud/hud.js`의 `button(1)` 끝부분(선택 항목 초기화, `return true`)이 주석 줄 끝에 붙어 실행되지 않는다. `80e0e10`부터 그렇고 검사는 통과한다. 통합에서는 건드리지 않았다. 의도인지 확인이 필요하다.
- H2 작업 카드가 오른쪽 아래 항법 판 윗부분을 가린다. `80e0e10` 캡처에서도 같다.
- 빌드 JS가 1 MB를 넘는다는 Vite 경고가 남아 있다(팀원 문서에도 기록됨).

## 6. 검증

검사 포트는 dev `5176`, preview `4176`이다(`5173`·`4173`·`5174`는 쓰지 않음). 브라우저 검사는 `MW_URL`로 주소를, `MW_OUT`으로 캡처 폴더를 받는다.

```bash
npm test
npx vite build
npx vite --host 127.0.0.1 --port 5176 --strictPort
MW_URL=http://127.0.0.1:5176/ npm run capture:integration
MW_URL=http://127.0.0.1:5176/ MW_OUT=<임시 폴더> npm run capture:stage1   # rover, stage2도 같은 방식
```

결과 수치와 실행 기록은 `docs/captures/integration-immersive/`의 `results.json`과 `regression/*.json`에 있다. 기존 `docs/captures/stage1*`, `stage2-hud-route`의 그림은 통합 전 화면이며 다시 찍지 않았다(나중 병합에서 이진 파일 충돌을 줄이려는 것).

### 실행 결과 (2026-11-15, Chrome headless, Apple M2 Pro)

| 검사 | dev `5176` | preview `4176` |
| --- | --- | --- |
| `npm test` (단위 검사) | 23개 통과 | 해당 없음 |
| `npx vite build` | 통과. JS 1,047.59 kB(gzip 332.26 kB), 큰 청크 경고 있음 | 해당 없음 |
| 통합 검사 (`capture:integration`) | 26개 통과 | 26개 통과 |
| stage1 | 32개 통과 | 32개 통과 |
| rover | 25개 통과. 단, 아래 "간헐 실패" 참고 | 25개 통과 |
| stage2 | 53개 통과 | 53개 통과 |

콘솔 경고는 stage1의 Canvas2D `willReadFrequently` 1건뿐이다(검사 스크립트가 지도 픽셀을 읽을 때 나오며 통합 전 결과에도 있다). 실패한 요청은 없다.

간헐 실패: rover의 `ride-gaze-does-not-steer`(로버를 탄 채 뒤를 보며 `W` 1.2초)가 dev에서 5번 중 2번 실패했다. 3.5 m/s면 약 4.2 m를 가야 하는데 0.30 m, 0.33 m만 갔다. 통과한 3번 가운데 값을 기록한 2번은 4.10 m였다. 임무 시계는 한 프레임에 최대 50 ms만 적분하므로 긴 프레임이 끼면 거리가 줄어든다. 실패한 두 번은 다른 작업 트리(`demo/v02-field`)의 브라우저 검사가 같은 GPU에서 돌던 때였다. 원인은 확인하지 못했다. 진단용으로 이 검사에 프레임 수·최대 프레임 간격·입력 해제 이벤트 기록을 넣었는데, 넣은 뒤 2번은 모두 통과했다(79프레임, 최대 간격 83~84 ms, 해제 이벤트 없음). 통합 전 `80e0e10`에서 같은 현상이 있는지는 재지 않았다. 실패한 실행의 결과는 `regression/rover-dev-stalled-run.json`에 남겼다.

검증하지 않은 것: 실제 마이크 음성 인식(headless 브라우저에서 `V`를 누르면 `not-allowed`로 실패해 대체 안내가 표시됨), 우주복·임무 상태 층을 연 상태의 글자 크기·대비 측정(stage2의 설계 측정은 층을 닫은 화면 기준), 모바일·저사양 GPU, 실제 사람이 포인터 잠금 상태에서 쓰는 조작감, 1600×900 이외 화면 크기에서의 층 위치.

## 7. `demo/v02-field`를 위에 합칠 때 겹칠 곳

`demo/v02-field`는 `80e0e10`에서 갈라져 진행 중이다. 내용을 보지 않고 쓴 예상이다.

- `src/main.js`: 통합본은 팀원 구조로 다시 짜였다. v02가 `80e0e10`의 `main.js`를 고쳤다면 대부분 충돌한다. 특히 키 처리(모드별 분기), `setMode`, 프레임 루프의 `hud.update` 호출, `goHud`.
- `src/hud/hud.js`, `src/style.css`의 HUD 구역: 버튼 2 분기, 상세 층 마크업, 범례 문구가 바뀌었다.
- `src/state/mission.js`: `habitatPose` 관련 네 곳과 `debugSetS`.
- `src/pad/pad.js`: `live()`의 대원 상태 줄.
- `index.html`: 팀원 것으로 바뀌었다(관제석·실내 보행 UI). v02가 시작 화면이나 `#css3d`를 고쳤다면 충돌한다.
- `tests/*.capture.mjs`: 진입 방식이 바뀌었다. v02가 새 검사를 만들었다면 `tests/lib/enter.mjs`의 `enterHud`·`enterPad`를 쓰도록 고쳐야 한다. 기지 안에서 `s = 0`으로 시작한다는 가정은 더는 맞지 않는다.
- `docs/captures/**`: v02가 기존 캡처를 다시 찍었다면 이진 파일은 한쪽을 고르면 된다(통합본은 기존 캡처를 건드리지 않았다).
- `package.json` scripts: `test`, `capture:integration`이 추가됐다.
