# HUD 설계 근거

2026-11-15 작성. HUD의 각 설계 결정을 출처에 연결한다. 출처는 팀 킷 조사 기록(`hackathon-kit/workspace/2026-nasa-space-apps-seoul/research/hud-*.md`, ideation 27.3·27.14~27.23)에 정리된 것만 썼고, 이번 작업에서 원문을 다시 열어 확인하지는 않았다. 근거가 없는 값은 "가정"으로 적는다.

적용 한계를 먼저 밝힌다. NASA-STD-3001 Vol 2 Rev E는 일반 승무원 시스템 표준이고 우주복 HUD 전용 수치가 없다. 부록 F의 대비 기준은 투과형 디스플레이를 다루지 않는다고 표준이 직접 밝힌다("have not been addressed in this revision"). 여기서는 그 값을 **유추 적용**했다. Joint AR 시험은 달 탐사용 시제품이고 표본이 5명이다.

## 1. 입력: 손 조작기와 음성

| 결정 | 근거 | 성격 |
| --- | --- | --- |
| HUD 조작은 팔뚝 손 조작기(순간 누름 버튼 2개 + 다이얼)로 한다 | Joint AR 시험: "a custom designed forearm-mounted hand controller, which consisted of two push buttons and a dial … navigate displays and declutter content" (NTRS 20250011653). 승무원이 조작기를 긍정 평가 | 출처 있음 |
| 마우스는 시선(머리 방향)만. HUD 항목은 클릭할 수 없다 | 가압 장갑으로는 키패드·마우스·터치가 적합하지 않음 (GECO, NTRS 20130014736) | 출처 있음 |
| 다이얼은 한 칸씩 끊어서 움직인다(휠 약 60 px = 1칸) | 순간 누름 버튼이 토글보다 약간 빠르고, 멈춤 홈 없는 다이얼이 가장 느림 (KLM 연구, NTRS 20230010234, N=6) | 출처 있음. 60 px는 가정 |
| 버튼 1 = 실행/확인, 버튼 2 = 접기/취소/정리(declutter), 다이얼 누름 = 미니맵 | Joint AR의 "navigate displays and declutter". 버튼별 기능 배정은 출처에 없음 | 배정은 가정 |
| 음성은 누르는 동안만 받아쓰기(push-to-talk), 표시는 "성능 미검증" | 팀 9차 결정에 음성 받아쓰기 포함. 우주복 안 인식 성능은 낮거나 미확인 (NTRS 20180006618, 20100039410) | 출처 있음. 실제 성능 미검증 |
| 우주복·임무 상태 층(계산 조건, 미연결 항목)은 버튼 2 또는 음성 "상세"로 여닫고, 누를 수 있는 단추를 두지 않는다 | 층의 내용은 `feat/immersive-mission-control`의 상태 패널. 조작 방식은 위 두 행(손 조작기, 클릭 불가)을 따름. Joint AR의 "declutter"와 같은 버튼에 배정한 것은 가정 | 내용은 팀원 구현, 배정은 가정 |
| 기지가 HUD에 지시를 보낼 수 있다. 대원이 버튼 1로 확인하고, 실행은 따로 선택한다 | Joint AR의 기본 조작에 관제(MCC) 원격 제어가 포함됨. 수신·확인·선택·실행 구분은 팀 개발 인계 AC-03·AC-06·AC-08 | 출처 있음. 상태 이름은 팀 기준 |

키보드 대역(우주복 하드웨어의 대용):

| 우주복 입력 | 키 |
| --- | --- |
| 다이얼 회전 | 마우스 휠, `[` `]` |
| 다이얼 누름 | `M` (미니맵 켜기/끄기) |
| 버튼 1 | `1` (`Enter`도 같음) |
| 버튼 2 | `2` |
| 음성 | `V` 누르는 동안 |
| 이동 | `W` (누르는 동안 경로 전진), `E` 로버 탑승/하차, `Shift` 로버 배속 |

음성 메모 화면에서는 키보드가 "음성 대체 입력(데모)" 칸에 들어가므로 `Enter`가 저장(버튼 1), 빈 칸에서 `2`가 취소(버튼 2)다. `Esc`는 브라우저가 포인터 잠금 해제에 먼저 쓰기 때문에 취소 키로 삼지 않았다.

2026-11-15 후속(브랜치 `demo/v02-field`): 팀 기능 정의 v0.2는 입력을 "음성 명령, 물리 버튼 2개"로 정했다. 그래서 새 기능은 다이얼 없이 버튼 2개와 음성으로 조작되게 했고, 항목이 둘 이상인 카드에서 버튼 2를 "다음 항목"으로 바꿨다. 다이얼 키(휠, `[` `]`, `M`)는 남아 있지만 팀 정의 입력이 아닌 데모 편의다. 음성은 메모 받아쓰기에 더해 고정 문법 명령을 받는다. 자세한 내용은 [stage3-v02-field.md](stage3-v02-field.md) 5절. 위 표의 다이얼 근거(Joint AR)는 출처 그대로이고, 팀 정의와 다르다는 점만 덧붙인다.

## 2. 표시

| 결정 | 근거 | 성격 |
| --- | --- | --- |
| 화면 위쪽에 항상 보이는 고정 띠: 임무 시계, 교신 상태와 마지막 수신 시각, 경보 상태 | NASA-STD-3001 Vol 2 Rev E 부록 F.4.2 f: "a common dedicated area for the display of key information to be visible at all times (e.g., time, system messages, alerts, communication status: Loss of Signal / Acquisition Of Signal)" | 출처 있음 (유추 적용) |
| 정보는 시야 가장자리에 두고 가운데는 비운다 | [V2 11022] "Suit helmet field of regard shall be unencumbered if helmet- or head-mounted displays are provided." HUD 주의 고착 연구의 처방(주변 배치, clutter 최소화)도 같은 방향 | 출처 있음. "가운데"의 범위(가로 30~70%, 세로 24~72%)는 가정 |
| 평상 정보는 단색 녹색 | Joint AR: "a monochromatic green display was used to model potential limitations of an early heads-up display system". 승무원이 익숙한 녹색 HUD 색을 좋게 평가 (NTRS 20250011653) | 출처 있음 |
| 색은 경보 의미에만 쓴다: 빨강=경고, 노랑=주의, 파랑=안내, 청록=오래된/없는 자료 | Table 10.3-1(Warning Red, Caution Yellow, Advisory Blue), 부록 F.6.4, Table F.5-1("Missing or stale data — Cyan"), [V2 10020] | 출처 있음 |
| 녹색 바탕 + 표준 경보색을 함께 쓴 이유 | Joint AR 도파관은 풀컬러가 가능했고 단색은 초기 시제품 제약을 흉내 낸 선택이었다. 그래서 평상 정보는 녹색으로 두되 경보는 표준 색 의미를 따르게 했다 | 두 출처를 합친 판단 |
| 글자 뒤에 어두운 판을 깐다 | 부록 F.5.10 f: 글자/배경 대비 6:1 이상(10:1 권장). 밝은 지형 위 투과 글자는 이 값을 못 맞춘다 | 출처 있음 (투과형은 표준 미정이라 유추) |
| 글자 크기: 대문자 높이 0.25° 이상 | 부록 F.5.1 g: "Character height must be a minimum of 0.25 deg, with 0.4 deg or greater is preferred" | 출처 있음 |
| 고딕체, 숫자는 고정폭, 약어가 아닌 글은 대소문자 혼용 | 부록 F.5.1 b·d·h | 출처 있음 |
| 걷는 중 기본 화면에 미니맵 없음. 다이얼을 눌러 펼침. 주의 구간에 다가가면 잠깐 자동 표시 | 개인 선택 27.14. Joint AR HUD는 지도를 포함하되 조작기로 넘기고 줄일 수 있었고, JETT3에서 지도는 주로 멈춰서 봄(NTRS 20230010686) | 팀 결정 아님 (개인 선택) |
| 도착은 알림으로 제안하고 대원이 확인해야 화면이 바뀐다 | 개인 선택 27.15, 팀 SC-10 | 배치는 개인 선택 |
| 복귀 여유(계획 기준 시각)와 산소를 따로 표시 | 개인 선택 27.19. xEVA ConOps: 소모품 계산은 일정 조정용, 안전 감시는 경보 계통 우선 (NTRS 20205008200) | 팀 결정 아님 |
| 주의 상태는 확인 전까지 계속 보인다 | [V2 10175] 근거 설명: 가장 높은 우선순위 경보를 승무원이 확인할 때까지 계속 알림 | 출처 있음. 이 데모에는 경보 확인·억제 조작이 아직 없음 |
| 기록에는 시각·위치가 자동으로 붙는다 | 팀 필수 페이지 H3 "메타데이터 자동 첨부" | 팀 확정 |

### 경보 등급 배정 (가정)

표준은 등급의 정의만 준다. 어떤 사건을 어느 등급에 넣을지는 이 데모의 가정이다.

| 사건 | 등급 | 이유 |
| --- | --- | --- |
| 회피 큐, 경로 이탈, 복귀 여유 2분 미만, 계획 체류 초과 | 주의(노랑) | "needs attention, but not immediate action" |
| 복귀 개시 기한 초과 | 경고(빨강 판 + 흰 글자) | 즉시 행동 필요로 가정 |
| 도착 알림, 기지 지시, 로버 탑승 안내 | 안내(파랑 띠 + 흰 글자) | Advisory |
| 교신 끊김과 마지막 수신 시각 | 청록 | stale data 색 |

빨강·파랑은 어두운 판 위에서 글자색으로 쓰면 6:1에 못 미친다. 그래서 색은 판이나 띠에 쓰고 글자는 흰색으로 했다.

2026-11-15 후속: 경보 확인 조작과 경보 5종(돌아설 시각 임박, 잔여 체류 10분, 버디 이탈, 교신 두절, 우주기상)이 `demo/v02-field`에 들어갔다. 등급 배정은 가정이다(우주기상만 경고, 나머지는 주의). 무음·억제 조작은 여전히 없다.

표준이 요구하지만 이 데모에 없는 것: 경보의 청각 신호(이중 부호화 [V2 10114]), 경보 무음·억제 조작([V2 10177], [V2 10116]), 우주복 압력·ppO2·ppCO2 표시([V2 11035]), 대사량 표시([V2 11038]).

## 3. 브라우저에서 잰 값

`npm run capture:stage2`가 실제 화면에서 계산한다. 결과는 `docs/captures/stage2-hud-route/results.json`의 `designAudit`.

- 글자 크기: 각 글자 요소의 대문자 높이(px)를 재고 두 가지 각도로 바꾼다. (가) 헬멧 시야각 기준: 화면 세로 62°를 창 높이에 대응시킨 값. (나) 책상 화면 기준: 96 dpi 화면을 60 cm에서 본다고 가정한 값. (나)가 더 엄격하다. 창 높이 900 px 미만에서는 글자가 14 px 아래로 줄지 않게 했다.
- 대비: HUD 글자를 투명하게 만든 화면을 찍어 각 글자 요소 자리의 실제 배경 픽셀을 읽고, 그중 가장 밝은 5% 지점의 휘도와 글자색 휘도로 대비를 계산한다(sRGB 상대 휘도, WCAG 식). 요소 자신의 테두리는 배경이 아니므로 2 px 안쪽만 읽는다.
- 가운데 비움: 이동 중 화면에서 가로 30~70%, 세로 24~72% 영역에 HUD 요소가 걸치는지 확인한다.
- 제외한 것: 나침반의 ▼·⌂ 기호, 띠 밖으로 밀려 잘린 나침반 눈금, 미니맵 캔버스 안의 글자.

측정 결과는 보고서와 `results.json`을 본다.

## 4. 근거가 없는 것 (가정)

보행 1.4 m/s, 로버 3.5 m/s, 배속 ×4, 복귀 개시 기한 T+25:00, 계획 체류 10분, 산소 분당 0.35%, 회피 큐 기준(경로 옆 6 m, 경사 12°), 이탈 경고 5 m, 버디 간격 4.5 m, 미니맵 범위 ±70 m, 판의 불투명도 0.88, 패널 위치(여백 8.5~9.5%).
