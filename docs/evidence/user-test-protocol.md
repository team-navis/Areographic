# 처음 보는 사람 관찰 계획 (준비만 함 · 아직 실행하지 않음)

목적: 처음 보는 사람이 이 데모로 무엇을 확인하려 했고, 어떤 자료가 판단에 영향을 줬고, 무엇을 모르는 채로 남겼는지 듣는다. 작업 효율이나 안전성 향상을 재는 시험이 아니며 그렇게 일반화하지 않는다.

## 참가자

- 2–3명. 이 데모를 본 적 없는 사람.
- 외부 참가자(팀 밖)와 내부 참가자(팀원·지인 중 개발에 관여한 사람)를 반드시 나눠 적는다. 내부 참가자의 기록은 "내부 점검"으로만 쓰고 사용자 근거로 세지 않는다.
- 기록에는 이름 대신 `외부-1`, `내부-1`처럼 적는다.

## 진행 (1인당 약 15분)

1. 안내 한 문장만 한다: "화성 기지에서 탐사 계획을 보내고, 대원이 되어 현장에서 암석을 살펴보고 돌아오는 데모입니다. 생각나는 것을 말하면서 해 주세요."
2. 관제자로 시작: 최종 검토에서 계획 확정(`계획만 전송`). 이동 가정이 무엇으로 되어 있는지는 진행자가 말하지 않는다.
3. 역할 전환 → 현장 대원: 에어록으로 걸어 나감 → 계획·패키지 확인 → 로버 탑승(E)과 Shift로 이동 → 도착 확인 → 현장 대조 → 관찰 대조(봄 / 못 봄 / 판단 불가) → 메모나 시료 기록.
4. 진행자가 관제 화면의 경보 전송을 대신 눌러 준다(우주기상 경보). 참가자가 확인 → 선택 → 복귀 개시를 스스로 하는지 본다.
5. 기지 도착 → 에어록 → 기지 안. 관제자로 돌아가 `② 현장 기록`에서 받은 기록과 후속 확인 과제를 보고 `임무 기록 내보내기`를 누른다.
6. 화면을 끄고 열린 질문 세 가지를 순서대로 묻는다. 보기를 주지 않는다.
   - "무엇을 확인하려 했나요?"
   - "어떤 자료가 판단에 영향을 줬나요?"
   - "아직 모르는 것은 무엇인가요?"

진행자는 막혀도 30초는 기다린다. 그 뒤에 돕되 도운 사실을 적는다.

## 적을 것

- 참가자 구분(외부 / 내부), 날짜, 기기와 브라우저, 걸린 시간.
- 개입: 진행자가 말하거나 대신 누른 모든 순간. 시각, 화면, 무슨 말을 했는지.
- 막힌 지점: 10초 넘게 멈춘 곳. 화면 이름, 참가자가 한 말, 풀린 방법.
- 세 질문의 답 원문. 요약하거나 고쳐 쓰지 않는다.
- 자료 출처 오해: 모의 값을 실측으로 알았는지, PIXL 지도를 헬멧의 실시간 분석으로 알았는지, 선 투영을 자동 인식으로 알았는지, 연출 바위를 실제 바위로 알았는지. 참가자가 한 말 그대로.
- 내보낸 임무 기록 파일(`marswalk-trace-…json`). 참가자 번호를 파일 이름에 붙여 보관한다.

## 보고할 때

- "N명 중 M명이 …라고 답했다"와 원문만 적는다. 외부와 내부를 따로 센다.
- 2–3명으로는 경향을 말할 수 없다. 관찰된 사례로만 쓴다.
- 실행하지 못했으면 "실행하지 않음"이라고 적는다.
