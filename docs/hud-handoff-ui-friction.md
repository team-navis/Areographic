# HUD 담당 인계: 텍스트와 조작 과정 정리 (UI friction review)

2026-11-15 작성. 검토 문서 "텍스트와 조작 과정 정리 점검"(`demo/v02-field` 60e7821 기준) 가운데 **HUD 쪽 항목**을 HUD 담당(`demo/frontend-v0.2`)에게 넘기는 목록이다. `demo/v02-field`에서는 `src/hud/*`를 고치지 않았다. PAD 쪽 항목(3의 PAD 부분, 4, 5)은 `demo/v02-field`에 반영했다([stage3-v02-field.md](stage3-v02-field.md) 3-6절).

줄 번호는 검토가 본 60e7821 기준이다. 이후 `src/hud/*`는 바뀌지 않았으므로 그대로 맞는다.

## 항목

### 1. 귀환을 선택한 뒤 다시 복귀 메뉴를 찾아야 한다 (동작 수정 필요)

- 현상: 관찰 대조 화면에서 경보를 확인하고 귀환을 고르면 경보에는 `choice=return`, `executedAt=null`이 남지만 화면은 관찰 대조 선택지(봄 / 못 봄 / 판단 불가 / 다음 항목 / 닫기)로 돌아간다. 그 선택지에 복귀 개시가 없다.
- 근거: `src/hud/field-hud.js:74–86, 103–108, 153–155`. 복귀 대기 카드는 `canReturnEarly()`를 함께 요구해서 현장 작업 중 관찰 화면에서는 그 분기로 들어가지 않는다.
- 최소 방향: 경보에서 귀환을 고르면 관찰 화면 위에 `복귀 개시`와 `보류`를 바로 낸다. 관찰 화면을 닫고 작업 목록에서 복귀 항목을 다시 찾게 하지 않는다.
- 지킬 것: 수신, 대원 확인, 귀환 선택, 실제 복귀 실행의 구분. 경보 확인이나 귀환 선택만으로 자동 이동시키지 않는다.

### 2. 같은 조작 방법을 여러 곳에서 반복한다 (축약 제안)

- 현상: 작업 카드에 버튼·다이얼 설명이 있고 화면 아래에도 버튼 2 다음 / 버튼 1 실행 / 음성 V 안내가 반복된다. 도착 때도 카드 본문, 실행 항목, 아래 안내가 같은 확인 행동을 설명한다.
- 근거: `src/hud/hud.js:49, 145–146, 158, 246–253`, `src/hud/field-hud.js:35, 101, 229`.
- 최소 방향: 기본 화면에는 지금 가능한 조작 안내 한 줄만 둔다. 처음 들어올 때 짧게 알리고, 전체 키 구성은 도움말을 열 때 보인다. 예: "목적지에 도착했습니다. 확인해야 관찰 화면으로 바뀝니다"와 아래의 같은 문장 대신 "Cheyava Falls 도착"과 "관찰 시작" 한 조작.
- 지킬 것: 키보드, 버튼 2개, 음성 입력 자체. 카드가 접혔을 때 보이지 않는 선택을 실행하지 않는 규칙.

### 3. 제품 사용보다 구현 설명이 먼저 보인다 — HUD 부분 (이동 제안)

- 현상: `작업 H2`, `팀 정의 v0.2`, `데모 편의(팀 정의 아님)` 같은 내부 표기가 현장 화면에 나온다.
- 근거: `src/hud/hud.js:160–167`, `src/hud/field-hud.js:35`.
- 최소 방향: 내부 페이지 번호와 개발 버전은 기본 화면에서 뺀다. 해시, 추출 성능, 세부 크레딧과 처리 방법은 자료 상세나 검수용 화면으로 옮긴다.
- 지킬 것: `모의 임무` 같은 짧은 전체 맥락. 실측·계산·모의를 가르는 짧은 라벨과 열어 볼 수 있는 출처. 자동 판단이 아니라 대원의 기록이라는 뜻, 광물 분석색과 실제 암석색의 차이, 미관측면, 추정 좌표는 그 자료를 해석하는 자리에 남긴다.
- 참고: PAD 쪽(패키지 버전·지문, 선·꼭짓점 수, 추출 시간, 긴 바닥글, 실측/계산/모의 띠)은 `demo/v02-field`에서 `자료·한계 ⓘ`와 "추출 정보 (검수용)" 안으로 옮겼다.

### 6. 현장 작업 목록이 현재 작업을 가린다 (노출 축소 제안)

- 현상: 도착 뒤 촬영, 메모, 현장 대조, 관찰 대조, 시료, 관심 지점, 복귀 7개가 한꺼번에 펼쳐진다. 촬영과 메모가 현장 대조보다 앞에 있고 `미완료`와 조작 안내가 반복된다.
- 근거: `src/hud/hud.js:69–76`, `src/hud/field-hud.js:83–95`.
- 최소 방향: 기본 카드는 현재 계획의 다음 작업, 진행 상태, 실행 조작 중심으로 줄인다. 전체 작업은 작업 목록을 한 번 열어 접근하고 순서는 자유롭게 바꿀 수 있게 둔다. 복귀를 긴 목록 끝에서만 찾게 하지 않는다. 경보 상황에서는 1번의 복귀 실행 카드가 먼저다.
- 지킬 것: 관찰 답을 저장하면 다음 미응답 항목으로 넘어가는 현재 연결. 저장 완료를 다시 확인시키는 단계는 추가하지 않는다.
- 참고: 작업 이름은 PAD 계획(`src/state/field-ops.js`의 `planDraft`)과 맞추면 된다. PAD는 "현장 대조 · 선 투영", "관찰 대조 · 관찰 리스트", "시료 기록", "촬영 마킹", "음성 메모"를 쓴다. HUD 기존 목록의 "촬영 · 영상 마킹", "메모 · 음성 받아쓰기/텍스트"가 아직 다르다(`src/hud/hud.js:69–76`).

### 7. 현재 상태와 맞지 않는 설명 (문구 수정 필요)

- 현상 ①: 기록 없음 안내에 "현장 화면은 이 암석을 3D로 재현하지 않습니다"가 남아 있다. 지금은 실측 Hazcam 메시를 쓴다.
- 현상 ②: HUD 상세의 산소 설명이 "외부 HUD에서만 진행"이라고 적는다. 지금은 관제 화면의 모의 진행(`pad-auto`)에서도 시계와 산소가 간다.
- 근거: `src/hud/hud.js:42, 167`, `src/world/field.js:23–35`, `src/state/mission.js`의 `tick`, `src/state/field-ops.js`의 모의 대원 진행.
- 최소 방향: 기록이 없으면 "기록 없음"만 보인다. 자료 설명은 "단일 시점 실측 메시, 미관측면 있음"처럼 실제 한계를 말하는 자리로 옮긴다. 산소 설명은 현재 계산 방식으로 고치고 자료 상세에 둔다.
- 지킬 것: 틀린 설명을 감추면서 모의 값을 실측처럼 보이게 만들지 않는다.

### 8. 임무 종료 뒤 기록까지 가는 길이 길다 (직접 연결 제안)

- 현상: 종료 카드가 "기록은 PAD에서 확인 · Esc 후 역할 전환"이라고 문장으로 안내한다.
- 근거: `src/hud/hud.js:169, 249`, `index.html:22–31`, `src/pad/field-pad.js:73–84`.
- 최소 방향: 종료 요약과 `기록 보기`를 두고, 고르면 현재 임무의 PAD 기록 화면으로 바로 간다. 역할 선택 화면을 다시 거치지 않는다.
- 지킬 것: 이 버튼으로 끝나지 않은 활동을 종료시키지 않는다. 역할 선택과 기지 돌아보기는 별도 접근으로 남긴다.
- 연결점(`demo/v02-field`에 이미 있음): PAD 기록 화면은 `window.__mw.fieldPad.setOpen(true); window.__mw.fieldPad.show('rec')`로 열린다. 관제자 역할 진입은 `window.__mw.enterRole('pad')`다(전환 애니메이션 포함). HUD에서 부를 공개 함수가 따로 필요하면 `src/main.js`에 추가해야 한다.
